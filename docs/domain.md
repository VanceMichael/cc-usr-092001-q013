# 领域约定

月饼跨境合规批次台围绕出口产品、配方版本、标签版式、目的国规则与物流批次保存可核对的业务记录。
外部主体使用不含真实身份信息的稳定引用编号（`D-SYD`、`C-AU-1` 等），时间一律采用带偏移量的
ISO 8601 字符串；材料事实只保存受控引用和 `sha256` 摘要。

## 主数据（不可变版本）

- **产品** `products`：SKU 与中文品名。
- **配方版本** `recipe_versions`：配料、过敏原集合、每 100g 营养事实，版本不可变，变更必须发新版本；
  内容摘要存于 `formula_digest`。
- **标签版式** `label_layouts`：语言集合、过敏原申报、营养声明、声称、包装规范。必须：
  - 包含 `zh`（保留传统中文标识）；
  - 绑定到该产品下确切存在的一个配方版本——装箱时还要与批次实际配方逐字一致。
- **目的国规则版本** `destination_rules`：强制语言、强制过敏原、营养表格式与必填营养素、容差、
  禁用声称、包装材料/标志要求，以及 `effective_from` 生效日期。规则不可变，临时更新通过发新版本实现；
  某时刻的有效规则取 `effective_from <= 该时刻` 的最新版本。

## 批次与数量守恒

生产批次有 `initial_qty` 与 `current_qty`。拆分（SPLIT）与合并（MERGE）都在 `batch_lineage`
留痕，守恒式统一为：

> 初始量 − 流出血缘（拆出/合出）+ 流入血缘（拆入/并入）= 当前量

合并仅允许同产品、同配方版本；已预留货物的批次不能合并。`GET /v1/conservation` 可对全部批次
随时核账，`GET /v1/batches/:id` 同时给出账面、已预留、已装箱数量。

分配（allocation）把批次数量预留给经销商订单；装箱（carton）逐件登记箱号、数量与所用标签。
分配量不得超过订单未满足量或批次可用量，装箱量不得超过分配余量，箱号唯一——重复扫描与
经销商重传都不增加货量。

合同价单独存于 `order_contract_prices`，任何读取与汇总路径都不连接该表。

## 逐件合规核验

装箱后对每箱调用检验：系统取**检验时刻**目的国现行规则，比对「批次配方事实 ↔ 标签声明 ↔ 规则要求」：
标签-配方版本一致、中文保留、强制语言、过敏原覆盖（配方事实 ∪ 目的国强制项）、营养格式/必填项/
数值容差、禁用声称、包装材料与标志。结论带逐项 `findings` 落库（`compliance_decisions`）。

不合格项**只阻断对应目的地的货物**：该箱置 `held`、不推进物流；同批次给其他目的地的箱不受影响。
被阻断的货物可离港前返工重贴（relabel，状态回到 PACKED）后重新检验；离港后只能召回。

## 物流生命周期

```
PACKED → INSPECTED → CUSTOMS_DECLARED → LOADED → DEPARTED → ARRIVED → SOLD_OUT
```

- 每个动作写一条 `carton_events`，重复扫描按状态机判定幂等，不产生任何增量；
- 装柜/离港/到港按货柜批量处理，事务内原子，一箱不合格整批不动；
- 已装柜箱重复扫入**另一**货柜会被拒绝；
- **离港即冻结**：离港时把当时有效的规则版本固化到箱（`rule_id_at_departure`）。

## 规则临时更新的三类分流

`POST /v1/rule-updates` 对某目的国在某时刻重放规则：

| 货物阶段 | 处理 |
| --- | --- |
| 已离港 / 到港 / 售罄 | 沿用离港锁定规则，冻结，不重评 |
| 已生产未离港（装箱后至装柜） | 按现行规则逐箱重评；不合格仅扣留对应目的地的箱 |
| 未生产（只有订单） | 不处理；将来检验时自动适用届时有效版本 |

## 召回

按 `RECIPE`（配方版本）、`LABEL`（标签版式）、`BATCH`（生产批次，沿拆分/合并血缘展开）三种范围
发起，结果逐箱固化到 `recall_findings`，并按「目的国 × 经销商」汇总受影响市场；已售罄箱
剩余包装记 0，在途/到港未售箱计入剩余包装数量。

## 出口解释与复购汇总

- `GET /v1/cartons/:ref/explain`：给出一箱为何获准出口——批次与配方版本及摘要、标签语言
  （含中文保留）、检验适用规则与离港锁定规则、全部决策与物流时间线，以及一段成文解释。
- `GET /v1/repurchase`：按经销商汇总订单数、复购单数、订购/满足数量、市场数、首末单时间，
  不包含任何价格字段。

## 交换事件

事件信封包含 `event_id`、`source`、`subject_ref`、`occurred_at`、`source_sequence`、
`event_type` 与 `payload`。

- `event_id` 重放完全幂等，返回首次结果；
- 同一 `(source, source_sequence)` 但不同 `event_id` 视为冲突拒绝；序号只在同一来源内递增；
- 保留原始 `occurred_at`，另记 `received_at`，绝不用到达时间覆盖；
- 载荷规范化后计算 `payload_digest`（sha256）；
- 载荷处理失败时事件不落库，可修正后以同一 `event_id` 重试。
